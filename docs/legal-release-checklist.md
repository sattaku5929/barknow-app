# WanTone 法務公開ゲート（2026-10-24 改訂草案）
本チェックリストは正式な法務レビュー・事業者の事実確認を代替しません。すべて完了するまで本PRをmainへマージしないでください。

## A. 公開主体・表示
- [ ] 正式な運営主体（法人なら登記名称と代表者氏名、個人事業なら法的氏名）・事業所在地・連絡先・個人情報保護窓口を確定
- [ ] 特商法に基づく表示の正式名称・住所・連絡先を整備し、アプリから容易に到達可能にする
- [ ] 相談受付メールと回答体制、個人情報開示請求の本人確認手続を実際に運用できる
- [ ] 文中の【公開前必須確認】【公開前要確認】を全て事実確認のうえ実データに差し替え
- [ ] 施行日・改訂日・旧版の変更履歴を確定し、ユーザーに通知する

## B. 課金契約・退会の整合性（最重要）
- [ ] Stripeサブスクリプションの自動更新、更新日、価格（税込）、初月割引、総額、回数・サービス提供時期を実際の決済設定と一致させる
- [ ] 解約受付方法・期限・解約処理の実装とユーザー向け表示を確認する。退会時に継続課金が残るか、実際に停止できるかをテスト
- [ ] 申込最終確認画面に法定事項と解約・返金条件を明瞭に表示（規約へのリンクだけでは代替できない）
- [ ] 既存のStripe webhookはcheckout.session.completedのみ処理しており、subscription.updated/deleted・invoice.payment_failedの追随動作を要追加確認
- [ ] サービス停止、コーチ都合のキャンセル、未提供回数の振替・返金等の運営ルールを確定

## C. 個人情報取扱いの裏づけ
- [ ] Supabase/Vercel/Cloudflare R2/Stripe/Google/メール/Slackなどの実際の委託先・国外処理・外国第三者への提供を台帳で確認
- [ ] コーチの契約形態と情報アクセス範囲・委託/第三者提供の法的根拠・秘密保持を確認
- [ ] バックアップ・ログ・決済履歴・退会データの保存期間と削除実装を検証
- [ ] 保有個人データの安全管理措置、開示・訂正・利用停止等の受付窓口を用意
- [ ] 実際のデータ処理に合ったポリシーであることを確認（広告利用やAI学習は別途同意が必要なら導線設計）

## D. 契約成立・証跡
- [ ] 新規登録・有料プラン申込前に規約とプライバシーポリシーへアクセスできる導線を追加
- [ ] 必要な同意・申込意思確認を明示的に取得し、同意日時・文書バージョンを改ざんしにくいサーバー側に記録
- [ ] 改訂時の適切な通知・同意を実装し、旧版を監査用に保持
- [ ] 日本の消費者契約法・個人情報保護法・特定商取引法に詳しい弁護士による最終レビュー
