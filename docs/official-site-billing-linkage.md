# 公式サイト申込み → WanTone月額会員の連携設計（2026-10-24）

## 決定した前提
- BarKnow公式サイトが**契約申込みの入口**。まだ公式サイト側の決済・申込受付システムはない。
- 無料診断を契約前の必須手順にするかは**未定**。本フローには含めない。
- ユーザーは公式サイトの月額プラン申込みCTAからWanToneのログイン／新規登録に進み、会員IDが確定した状態で月額会員登録・決済を行う。
- アプリの「契約・お支払い」は**既存の有料契約が確認できた本人だけ**に表示する。単なるコーチングの相談申込み、無料診断、コーチ割当だけでは表示しない。
- Stripeは既存実装上の決済候補。公式サイトで独自の会員DBを作らない。

## フロー
1. 公式サイト `/app/` の「コーチングのプラン詳細・お申し込み」を押す（対応サイトPR #38）
2. WanTone `/plans/coaching` でログインまたは新規登録。元のプランURLに戻る
3. 表示価格・更新周期・初月割引・解約条件・サービス提供時期等を確認した後、認証済みセッションで `POST /api/stripe/checkout` を要求
4. **サーバーだけが** Auth のユーザーIDから Checkout Session `client_reference_id` / metadata を設定する。利用者が提示するIDは信用しない
5. Stripe Checkoutで月額契約を申込み。署名検証済みWebhookが `wt_subscriptions.user_id` に契約情報を保存
6. WanToneマイページの契約状態APIが本人IDでDBの契約を読み、Stripe APIでも顧客ID・状態を照合してメニューを表示
7. メニューからオンデマンドでStripe Billing Customer Portalの短期セッションを生成し、月額契約の確認・解約に進む
8. 解約完了・期間終了・決済失敗などStripeイベントによって契約状態を同期する
9. 継続課金が有効なままアプリを退会しようとしたときは、課金契約の確認と解約を優先し、データ削除で解約導線を失わせない

## 絶対に避けること
- メールアドレスの一致だけで契約を紐付ける
- ユーザーが送信した customer_id / subscription_id からポータルを作成する
- フロントエンドの「申込み済み」フラグだけで有料権限を与える
- 自分の契約以外の情報を閲覧・停止できるようにする
- Stripeの契約が継続中なのに、WanTone会員を削除してしまう
- 課金・解約が実装・動作確認される前に本番で有料申込みを開始する
