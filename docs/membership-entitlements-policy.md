# WanTone 無料・月額会員の権限制御仕様（Phase 1：設計のみ）

作成日：2026-10-25

## 事業方針
「日々の記録とお世話は無料」「担当コーチがつき、チャットとオンライン面談を受けられるのが月額プラン」。

| 機能 | 無料会員 | 月額会員 |
| --- | --- | --- |
| 愛犬の登録・プロフィール | ○ | ○ |
| Daily Check / Quick Log | ○ | ○ |
| 変化・できごとの傾向 | ○ | ○ |
| 日々のお世話・カレンダー | ○ | ○ |
| コーチングの相談・プラン案内を見る | ○ | ○ |
| 担当コーチの伴走 | ― | ○（担当確定後） |
| 担当コーチとのチャット | ― | ○（担当確定後） |
| オンラインコーチング予約・実施 | ― | ○（担当確定後） |

- コーチングの事前相談・有料申込の受付形態、および「無料診断」の有無は今後検討。**月額会員の前に無料診断を必須とはしない**。
- 個別オンライン面談の料金、回数、所要時間、繰越・返金条件等は未確定。「月4回」の既存画面文言は最終契約内容ではないため公開前に整合確認。
- 有料会員は無料機能もすべて利用できる。

## 会員と担当コーチの状態を分離
`lib/membership.ts` の `plan_status`→`MembershipState`（standard / active / payment_attention / ended）を契約の参照元とする。決済事業者のcustomer_id、Stripe固有の値やメールの一致を権限条件に使わない。

`lib/entitlements.ts` の純関数 `resolveOwnerEntitlements()` によって、月額契約とコーチ割当を別々に判定する。

- 無料：記録等の基本機能は利用可能、コーチ付き機能は対象外（プラン紹介を見せる）
- 有料・コーチ未確定：有料会員だがコーチ付き機能は「担当調整中」
- 有料・担当確定済み：`assigned_coach_id` があり、`owner_confirmed_at` があり、申込ステータスが `assigned / consulting / payment_pending / active` のいずれか→チャット・オンラインコーチングを利用可能
- 支払い確認中：現行の仕様では新たな有料利用権を付与しない。猶予期間を設けるかは社内で後日決定
- 契約終了：新たな有料機能は開始できない。過去の記録・履歴を勝手に削除しない
- Coach / Admin：オーナーの月額区分とは異なる権限。管理側の権限判定は`wt_user_roles`のまま

## 重要：この段階で本番のアクセス制限は変更しない
現状の本番Supabaseの読み取り結果では、`wt_subscriptions`が0件、`wt_coaching_applications`が2件、`wt_coach_messages`が44件、`wt_online_sessions`が3件（2026-10-25時点）。

現行の`wt_coach_messages`はオーナー本人であればINSERTできるRLS、`wt_book_online_session`は担当確定を検証するが月額契約は検証していない。**フロントだけの非表示を正式な権限管理だと誤認しない**。即時に月額ステータスをRLSで強制すると既存の検証ユーザーを停止させる。

本PRではポリシー定義、テスト、プラン紹介ページの比較表示のみを追加し、DB / RLS / RPC / API認証 / 既存のチャット送信・予約処理は変更しない。

## 実際の課金開始前に必要な次フェーズ
1. **既存検証ユーザーと履歴の棚卸し**：既存のコーチ付きオーナーを継続利用できる検証枠として扱うか、課金開始時に有料移行するかを明確にする。user_metadataの自己申告フラグは権限に使用しない
2. **契約の正規化**：Stripe等から入る契約イベントを決済事業者非依存の会員ステータスに集約。月末解約予約でも提供期間中は権限を維持する。決済失敗や返金を含め明確化
3. **サーバー側での厳格な権限制御**：チャットのINSERT RLS、アップロード、オーナーの予約API、`wt_book_online_session` RPCなど**すべての書き込み経路**で「有効契約かつ担当コーチ確定」の検証を行う。DB移行は本番 read-only スナップショット→ローカルテスト→本番適用→データ保全確認が必須
4. **表示の切り替え**：有料未加入はチャット・オンライン予約のプレビュー/プラン紹介、決済済み担当調整中は待機メッセージ、担当確定済みで利用可能へ
5. **終了・解約時の対応**：新規送信/新規予約の可否と既存予約履行/履歴閲覧を別に定義。既存契約の法定義務やサポート要件を考慮して例外処理を明示
6. **テスト**：オーナー無料/有料/支払失敗/キャンセル、担当未確定/確定/辞退、複数ユーザー不正操作、Coach/Admin、過去データ参照/既存予約、決済Webhookの競合順序等

**Phase 1のmain反映は新たな課金機能を開放しない。** 本番での有料化の強制は上記確認・承認後の別PRで行う。
